# HebSub — כתוביות עברית לסרטים

אפליקציית אנדרואיד (Kotlin) שמוסיפה **מסלול כתוביות בעברית** לסרט קיים — מקובץ
במכשיר או מקישור להורדה — עם דגש על **תרגום שמשקף כוונה** ועל **פרטיות מלאה**
(אף פרט משתמש או מכשיר אינו נחשף ברשת).

יעד: **Samsung Galaxy A56 5G** (`SM-A566B/DS`), Android 15+ / One UI 7, `arm64-v8a`,
תואם 16KB page size.

**גרסה נוכחית בקוד: 3.8** (`app/build.gradle.kts` → `versionName`).
הבדל 3.8 מ‑3.7 הוא רק מפתח החתימה הקבוע (ראו "חתימה" למטה); מי שעובד עם 3.7 יכול להישאר.

המסמך הזה נועד לשני קוראים: מי שמתקין ומפעיל את האפליקציה (החלק הראשון), ומי
שפותח את הקוד — מתכנת או מודל AI — וצריך להבין **מה יש כאן, איך זה זורם, ולמה
זה בנוי כך ולא אחרת** (החלק השני, "מבנה האפליקציה").

## חלק א׳ — התקנה ושימוש

### ⬇️ הורדת APK מוכן להתקנה
ה‑APK נבנה אוטומטית ב‑GitHub Actions (workflow: **Build HebSub APK**) ומתפרסם בשני מקומות:
1. **Release** בשם `hebsub-latest` — קובץ `HebSub-debug.apk` להורדה ישירה:
   `https://github.com/lior77/book-gage/releases/download/hebsub-latest/HebSub-debug.apk`
2. **Artifact** של ההרצה תחת לשונית *Actions* בריפו.

**התקנה:** אפשרו במכשיר "התקנה ממקור לא ידוע" → התקינו את `HebSub-debug.apk` → בפתיחה
ראשונה אשרו את ההרשאות → בהגדרות הזינו את המפתחות (ראו למטה).

**שדרוג:** עד גרסה 3.7 כל בנייה נחתמה במפתח debug חדש, ולכן כל עדכון חייב הסרה של
הגרסה הקודמת — והסרה מוחקת את נתוני האפליקציה, כולל המפתחות. מגרסה 3.8 המפתח קבוע
ומחויב לריפו (`app/debug.keystore`), כך שעדכונים מתקינים אחד על השני. **המעבר
מ‑3.7 (או ישן יותר) ל‑3.8 ומעלה דורש הסרה אחת אחרונה**; אחרי זה — לא עוד.
שמרו את המפתחות לקובץ `HebSub-keys.json` לפני ההסרה וטענו אותם בחזרה אחריה.

### מסך הבית — שלוש אפשרויות

| אפשרות | מה היא עושה |
| --- | --- |
| **הוספת מסלול כתוביות בעברית** | בחירת וידאו (או קישור), השגת כתוביות, תרגום, ויצירת MKV עם מסלול עברית. |
| **עריכת עיצוב הכתוביות** | שינוי הרקע, הגודל, המיקום, המרווחים וההיסט במסלול קיים — בלי לתרגם מחדש. |
| **הוספת נתוני סרט** | הזנת קישור IMDb: יצירת PDF ותמונת הסרט, שמות קבצים קנוניים והטמעת הנתונים בקובץ — **בלי לגעת במסלול הכתוביות**. |

בכל מסך יש שני כפתורי יציאה: חזרה למסך הבית, או סגירת האפליקציה.

### מאיפה מגיעות הכתוביות

לפי הסדר, הראשון שמצליח מנצח (בקוד המספרים 1.1–1.6 נשמרים ביומן; במסך מוצגים השמות בלבד):

| # | מקור | מה קורה אחר כך |
| --- | --- | --- |
| 1.1 | **רצועה עברית מוטמעת** בקובץ | אין מה לתרגם ואין מה לתזמן |
| 1.2 | **התאמת hash בעברית** (OpenSubtitles) | כתוביות שהועלו עבור הקובץ הזה בדיוק |
| 1.3 | **התאמת hash באנגלית** | תרגום |
| 1.4 | **קובץ כתוביות שהעליתם** | תרגום (אם אינו עברי) |
| 1.5 | **רצועה זרה מוטמעת** | תרגום |
| 1.6 | **תמלול פס הקול** (Deepgram) | תרגום |

מסך ההתקדמות מציג את ששת השלבים בזמן אמת: מה רץ עכשיו (מודגש), מה שימש (✓), מה
לא רלוונטי או לא נמצא (–), ומה נכשל (✕), עם הערה קצרה ליד כל שורה.

**האפליקציה אינה מחפשת כתוביות לפי שם או IMDb.** חיפוש כזה מוצא את הסרט הנכון אבל
לא את הגרסה (ה‑cut) הנכונה, וזה בדיוק מה שגרם בעבר לכתוביות שאינן מסונכרנות. מה
שנשאר הוא חיפוש לפי hash של הקובץ — שהוא בדיקת זהות, לא חיפוש. מי שרוצה כתוביות
מהרשת לסרט שאין לו התאמת hash, מוריד אותן בעצמו (ראו "איך לבחור קובץ כתוביות
מהרשת" בהמשך) ומעלה אותן דרך 1.4.

### תזמון
כל מקור נשמר **בתזמון המקורי המדויק שלו**, בלי יוצא מן הכלל: זמן ההופעה של שורה
לעולם אינו זז. מותר רק להאריך את **סוף** הכתובית אל תוך השקט שאחריה (למהירות
קריאה סבירה ולזמן הצגה מזערי), ולעולם לא לתוך הכתובית הבאה.

סנכרון אוטומטי מול פס הקול נוסה והוסר: קו הזמן של הדיבור הגיע מתמלול, ותמלול
מזהה מוזיקת רקע כדיבור, כך ששיר מלווה נראה לאלגוריתם זהה לדיאלוג והיישור נעגן
עליו. במקומו יש **היסט ידני** במסך עריכת הכתוביות: מי שצופה בסרט יודע בכמה
הכתוביות חורגות, ואומר זאת.

### תרגום
Claude (אם הוזן מפתח) או ML Kit מקומי. לפני האצוות נשלחת בקשה קטנה אחת שמקבעת את
האיות העברי של השמות שחוזרים בסרט, כך ששתי אצוות לא יכתבו את אותה דמות בשתי
צורות. שורות שהמתרגם בענן לא החזיר מבוקשות שוב בקבוצות קטנות ואז אחת‑אחת; מה
שעדיין נשאר בשפת המקור מושלם על ידי ML Kit, כדי שלעולם לא תופיע שורה זרה באמצע
העברית.

### עיצוב הכתוביות (סעיפים 9–10)
בעת יצירת המסלול בוחרים בין **כתוביות רגילות (SRT)** לבין **ASS מעוצב** עם פלטה
אפורה חצי‑שקופה מאחורי הטקסט (מסתירה כתוביות "צרובות" בתמונה). ברירות המחדל ל‑ASS:
שקיפות 10%, גודל פונט 28, גובה פלטה 3, אורך פלטה בצדדים 12, גובה מתחתית הפריים 5,
מרווח שורות נוסף 4. סימון אחד הופך את הפרמטרים לברירת המחדל לסרטים הבאים (סעיף 10).
במסך העריכה יש **תצוגה מקדימה** על פריים אמיתי מהסרט.

#### היסט ידני (סנכרון)
כפתורי היסט: ‎±0.5‎, ‎±1‎ ו‑‎±5‎ שניות, בטווח ‎±120 שניות. ערך חיובי מאחר את
הכתוביות, שלילי מקדים אותן. ההיסט משנה **רק** את חותמות הזמן.

הגופן העברי (Alef) מוטמע כ‑attachment ב‑MKV: בלעדיו libass נשאר בלי גליפים עבריים
והמסלול לא מוצג כלל (לא ריבועים — פשוט כלום).

### הודעת הסיום
בסיום ריצה מוצלחת מוצגת התיקייה, הקבצים שנוצרו, ורשימת **בעיות בקובץ הסופי** אם
היו (שורות שלא תורגמו, קטעים שלא תומללו, כתוביות מהירות מדי לקריאה, MKV שלא נוצר,
מודל תמלול חלופי…). "✓ לא זוהו בעיות" אומר שאין צורך לפתוח את היומן.

### מפתחות API (בהגדרות)

| מפתח | לְמה | חובה? |
| --- | --- | --- |
| **Anthropic (Claude)** | תרגום איכותי ותקציר בעברית | מומלץ מאוד (אחרת ML Kit מקומי) |
| **OpenSubtitles** | התאמת כתוביות לפי hash | לא |
| **Deepgram** | תמלול פס הקול | לא (נדרש לסרט בלי כתוביות) |
| **OMDb** | נתוני הסרט, התמונה וה‑PDF | נדרש ל"הוספת נתוני סרט" |

בשמירת כל מפתח מתבצעת בדיקת חיבור אמיתית ומוצגת אינדיקציה. אפשר לשמור את כולם
לקובץ `HebSub-keys.json` בתיקיית HebSub ולטעון אותם בחזרה לאחר התקנה מחדש.
אם ריצה מסתיימת ב"לא נמצאו כתוביות", ההודעה מציינת אילו מפתחות חסרים.

### מבנה התיקיות במכשיר
```
<אחסון משותף>/HebSub/
    HebSub-keys.json                 ← גיבוי המפתחות (אופציונלי, ידני)
    crash-<זמן>.txt                  ← דוח קריסה, רק אם האפליקציה קרסה
    <שם הסרט>-<שנה>/
        <שם>.he.mkv                  ← הוידאו עם מסלול העברית (+ מטא‑דאטה, פוסטר, גופן)
        <שם>.he.srt                  ← מסלול העברית כ‑SRT — תמיד נכתב, גם כשנבחר ASS
        <שם>.he.ass                  ← מסלול העברית המעוצב (רק כשנבחר ASS)
        <שם>.deepgram.jsonl          ← התשובות הגולמיות של התמלול (רק במקור 1.6)
        <שם>.pdf                     ← דף הסרט הדו‑לשוני (רק עם קישור IMDb)
        <שם>.poster.jpg              ← תמונת הסרט (רק עם קישור IMDb)
        <שם התיקייה>.txt             ← יומן מפורט של הריצה
```
כשמסומן "מחיקת קבצי ביניים" (ברירת המחדל) הווידאו המקורי, האודיו שחולץ, כתוביות
המקור שהורדו/חולצו וקבצי הביניים נמחקים בסוף; ה‑SRT וה‑jsonl נשמרים בכוונה — ה‑SRT
הוא הקובץ היחיד שנגן יטען ידנית, וה‑jsonl הוא הראיה לכל טענה על "כתוביות חסרות".

### פרטיות (סעיף 12)
- אין SDK אנליטיקס או טלמטריה. User‑Agent גנרי, ללא cookies, ללא מזהי מכשיר.
- מפתחות API מוזנים חד‑פעמית ונשמרים **מוצפנים** (Android Keystore /
  `EncryptedSharedPreferences`) — לעולם לא בקוד, לא בריפו ולא ברשת.
- הערך היחיד שנשלח ל‑OpenSubtitles הוא ה‑hash של הקובץ המעובד.
- לענן התרגום נשלח טקסט הכתוביות בלבד; לתמלול נשלח האודיו בלבד.
- היומן, דוחות הקריסה והתשובות הגולמיות נשארים במכשיר.

### איך לבחור קובץ כתוביות מהרשת (למקור 1.4)
כשאין התאמת hash, מורידים קובץ ידנית. מה שקובע התאמה הוא **הגרסה של הווידאו**, לא
השם: משך זהה (עד שנייה), אותו שם release (למשל `WEB-DL`/`BluRay` ואותה קבוצה), ו‑fps
תואם (קובץ ל‑25 fps על וידאו של 23.976 סוטה 4.27% ומצטבר לדקות). בדקו בנגן שהכתובית
האחרונה נופלת על השורה האחרונה בסרט; היסט קבוע מתקנים במסך העריכה, סחיפה
(drift) — לא, ואז צריך קובץ אחר. הכלי `tools/compare_subs.py` משווה שני קבצים חלון‑חלון.

### בדיקה מקצה‑לקצה (על ה‑A56)
1. **קובץ עם מסלול עברית מוטמע** → זיהוי מיידי, MKV בלי תרגום.
2. **קובץ עם מסלול אנגלית בלבד** → תרגום, בתזמון המקורי המדויק.
3. **העלאת קובץ כתוביות** → מתורגם, בתזמון המקורי של הקובץ.
4. **קובץ בלי כתוביות כלל** → תמלול (דורש מפתח Deepgram) ואז תרגום. בדקו את
   `speech coverage:` ביומן ואת רשימת הבעיות בסיום.
5. **ASS** → פתחו ב‑VLC ובדקו את הרקע, הגודל והמיקום; ואז מסך העריכה ותצוגה מקדימה.
6. **היסט ידני** → אם הכתוביות חורגות, תקנו במסך העריכה ובדקו שוב בנגן.
7. **הוספת נתוני סרט** → ודאו ש‑PDF ותמונה נוצרו, שהשמות עודכנו, **ושמסלול הכתוביות
   נשאר בדיוק כפי שהיה**.

### 1. שני מודולים, ולמה

```
HebSub/
├── core/    :core  — Kotlin JVM טהור. בלי Android, בלי רשת, בלי קבצים.
│                     כל הלוגיקה שאפשר לבדוק בבדיקת יחידה: פענוח וכתיבה של SRT/ASS,
│                     חיתוך ועיטוף שורות, תזמון, פיצול תמלול לכתוביות, בניית בקשות
│                     ל‑Claude/OpenSubtitles ופענוח התשובות.
└── app/     :app   — Android (Compose). הכול שנוגע למכשיר: UI, הרשאות, אחסון,
                      הגדרות מוצפנות, HTTP, FFmpeg, ML Kit, שירות רקע, ה‑pipeline
                      שמחבר את הכול.
```

`:core` הוא **build נפרד** (`includeBuild("core")` ב‑`settings.gradle.kts`) שמוחלף
אוטומטית בתלות `com.hebsub:core` של האפליקציה. הסיבה: אפשר להריץ
`cd core && gradle test` בלי Android SDK, וכל תיקון בלוגיקה (ורוב התיקונים בפרויקט
הזה היו בלוגיקה — תזמון, פיצול, פענוח) נבדק תוך שניות. **כלל אצבע: אם פונקציה לא
צריכה `Context`, `File` או רשת — היא שייכת ל‑`:core` ויש לה בדיקה.**

88 בדיקות יחידה בארבעה קבצים:
```bash
cd core && gradle test        # BUILD SUCCESSFUL
```

### 2. הזרימה של ריצה אחת ("הוספת מסלול כתוביות")

```
MainActivity (Compose)
   │  בחירת קובץ / קישור
   ▼
ProcessingService (foreground service)            app/service/ProcessingService.kt
   │  1. מעתיק/מוריד את הווידאו ל‑cache
   │  2. עוצר ומחכה למשתמש: שם, שנה, IMDb, קובץ כתוביות, SRT/ASS, עיצוב   (PipelineBus.awaitVideoInfo)
   │  3. OMDb (אם יש IMDb+מפתח) → שם תיקייה קנוני
   │  4. מעביר את הווידאו ל‑HebSub/<שם>-<שנה>/
   ▼
SubtitlePipeline.run()                            app/pipeline/SubtitlePipeline.kt
   │  probe (ffprobe): רצועות כתוביות, שפת אודיו, משך
   │
   ├─ acquire()  — סדר המקורות 1.1 → 1.6, הראשון שמחזיר cues מנצח
   │     1.6 = SpeechTranscriber                  app/pipeline/SpeechTranscriber.kt
   │
   ├─ translate() — ClaudeCloudTranslator או MlKitTranslator, ואז fillUntranslated()
   │
   ├─ SubtitlePostProcessor.process()            core/text/SubtitlePostProcessor.kt
   │     פיצול → עיטוף → מהירות קריאה → משך מזערי → הסרת חפיפות → RTL → מספור
   │
   ├─ writeSubs()  — תמיד <שם>.he.srt; בנוסף <שם>.he.ass כשנבחר ASS
   │
   ├─ OMDb enrich — פוסטר, PDF, תקציר בעברית (ClaudeText)
   │
   └─ mediaTool.remuxWithHebrewAndMeta()          app/src/ffmpeg/.../FfmpegMediaTool.kt
         MKV חדש: וידאו+אודיו בהעתקה, מסלול עברית, מטא‑דאטה, פוסטר, גופן; ffprobe לאימות
   ▼
PipelineState.Success(folder, srtName, mediaName, issues)  ← המסך מציג, כולל רשימת הבעיות
```
בכל שלב: `RunLog.log()` ליומן המלא, `RunLog.issue()` לרשימת הבעיות שתוצג בסיום,
`PipelineBus.update()`/`step()` למסך ההתקדמות.

### 4. החלטות תכנון — ולמה

כל אחת מההחלטות הבאות היא תוצאה של בעיה שנצפתה בסרט אמיתי. מי שמשנה אותן צריך
לדעת מה הן פתרו.

#### 4.1 חיפוש לפי hash בלבד, בלי חיפוש לפי שם
חיפוש לפי שם/IMDb החזיר כתוביות של גרסה אחרת של הסרט ("הסרט הנכון, ה‑cut הלא נכון")
והתוצאה הייתה כתוביות שחורגות בדקות. `moviehash` מתאים רק לקובץ זהה בייט‑לבייט, ולכן
מה שהוא מחזיר מסונכרן מעצם ההגדרה. המחיר: לרוב הסרטים אין התאמה, ואז עוברים ל‑1.4–1.6.

#### 4.2 אין סנכרון אוטומטי; יש היסט ידני
יישור לפי פס הקול נבנה והוסר: ציר הזמן של הדיבור הגיע מתמלול, והתמלול "שומע"
מוזיקה כדיבור. `SubtitleTiming.shift` + כפתורי ההיסט במסך העריכה מחליפים אותו.
היסט קבוע — נפתר שם. סחיפה (fps שונה) — לא, וזה מתועד למשתמש.

#### 4.3 זמן התחלה קדוש
`SubtitleTiming` מזיז רק סופים, ורק אל תוך השקט. `startTimesUnchanged` רץ ב‑pipeline
לפני הכתיבה, וכישלון שלו מחזיר את הגרסה הלא‑מתוזמנת. זו ההגנה על סעיף 7 במפרט.

#### 4.4 תמלול (1.6) בארבע שכבות
סרט שלם שנשלח ל‑Deepgram בבקשה אחת חזר עם כמעט חצי מהדיאלוג חסר. הפתרון
(`SpeechTranscriber`, גרסאות 3.6–3.6.1):
1. **חילוץ הדיאלוג ולא המיקס** — ערוץ מרכז ב‑5.1, `dialoguenhance` בסטריאו,
   `speechnorm`, FLAC 16 kHz מונו ללא איבוד.
2. **קטעים של 10 דק׳ עם חפיפה של 5 שנ׳** (`SpeechChunks`), במודל `nova-3` עם
   `language=` מפורש (מה‑container או מזיהוי על הקטע הראשון). `smart_format` כבוי כי
   הוא מוחק מילים; `punctuate` דלוק כי הפיצול לכתוביות נשען על סימני פיסוק.
3. **מעבר שני על חורים**: כל קטע ≥45 שנ׳ בלי מילים נמדד ב‑`silencedetect` **על
   קובץ המקור** (על האודיו המנורמל הכול נראה "לא שקט"); אם ≥25% ממנו אינו שקט, הוא
   נחתך, מוגבר יותר (`afftdn` + `speechnorm` חזק) ונשלח שוב. תקרה: 12 קטעים / 25 דק׳.
4. **דוח כיסוי** ביומן (`speech coverage:`), התשובות הגולמיות ב‑`.deepgram.jsonl`,
   ו‑`RunLog.issue` על כל קטע שנכשל / חור שנשאר / מודל חלופי.

`SpeechSegmenter` הופך מילים לכתוביות. הגרסה הראשונה חתכה בכל הפסקה של 0.6 שנ׳
ופיצלה דיבור איטי לכתוביות של מילה אחת; היום הפסקה חותכת רק כשיש ≥24 תווים,
והפסקה ארוכה (1.5 שנ׳) חותכת תמיד.

מדד האיכות (סרט Plan B מול כתוביות מקצועיות, `tools/compare_subs.py`): 3.5 — 54%
מזמן המסך של הייחוס ו‑4 חלונות אבודים; 3.6 — 81% ו‑0 חלונות אבודים.

#### 4.5 תקציב הטוקנים של Claude
Sonnet 5 "חושב" כברירת מחדל, והחשיבה נספרת בתוך `max_tokens`. עם 4096 החשיבה אכלה
את התקציב, התשובה חזרה ריקה או קטועה, וניסיונות חוזרים החזירו אותו דבר — וכך נשארו
שורות בספרדית. התיקון (3.5): `max_tokens` 16000, `output_config.effort` — "medium"
לאצוות ו‑"low" למילון השמות (haiku‑4‑5 לא תומך ב‑`effort` ומקבל 8192 בלי), לוג
של `stop_reason` ו‑usage בכל תשובה, ופרסר salvage שמציל זוגות שלמים מ‑JSON קטוע.
`RunLog.issue` מדווח כשתשובה נקטעה ב‑`max_tokens`.

#### 4.6 צמצום במקום ויתור
אצווה שחוזרת ריקה היא בדרך כלל כמה שורות בעייתיות שמפילות איתן את השאר.
`ClaudeCloudTranslator.narrow` מבקש שוב בקבוצות של 8 ואז אחת‑אחת (עד 16 בקשות
בודדות לאצווה). מה שעדיין חסר עובר ל‑ML Kit ב‑`fillUntranslated`, כדי ששורה זרה
לעולם לא תגיע למסך. שני המצבים מדווחים ברשימת הבעיות.

#### 4.7 תקן קריאה: 42 תווים, 2 שורות, 17 cps, 833 ms
לפי Netflix Hebrew Timed Text Style Guide. `CueSplitter` מפצל, `LineWrapper` מעטף,
`SubtitleTiming.ensureReadingSpeed` מאריך סופים (רק אל השקט), `removeOverlaps`
מבטיח שכתובית נעלמת לפני שהבאה מופיעה (ASS מציג חפיפות בערימה). "יותר מ‑10% מהכתוביות
מהירות מדי" הופך ל‑issue.

#### 4.8 ASS: פלטה, גופן מוטמע, ותמיד גם SRT
ASS נבחר כי SRT לא יכול לצייר רקע, ורקע הוא מה שמסתיר כתוביות צרובות. libass במכשיר
אין לו גופן עברי, ולכן Alef מצורף ל‑MKV כ‑attachment **עם mimetype** — בלעדיו המסלול
מוצג ריק. ה‑SRT נכתב תמיד לצד ה‑ASS כי הוא הקובץ היחיד שנגן מאפשר לטעון ידנית.

#### 4.9 remux בלי קידוד מחדש, ואימות אחרי
כל פעולת FFmpeg על הווידאו היא `-c copy`: מהיר, ללא איבוד, והכתוביות הקיימות לא
נפגעות. אחרי כל כתיבה ffprobe קורא את הקובץ ומוודא שהמסלול העברי (והפוסטר, והגופן)
באמת שם; אם לא — `RunLog.issue`. ב"הוספת נתוני סרט" כל ה‑streams ממופים במפורש כדי
שהמסלול העברי יצא בייט‑לבייט זהה.

#### 4.10 שירות foreground + PipelineBus
ריצה יכולה להימשך עשרות דקות. `ProcessingService` מחזיק אותה בחיים ברקע;
`PipelineBus` הוא `StateFlow` יחיד שה‑UI צופה בו, וכשה‑pipeline צריך החלטה מהמשתמש
(שם, שנה, אפשרויות) הוא נעצר על `CompletableDeferred` עד שהמסך משלים אותו. ביטול
מהמסך מבטל את ה‑scope; קבצי הביניים נשארים בתיקייה בכוונה, והיומן נכתב ב‑`finally`
תמיד.

#### 4.11 יומן, רשימת בעיות, ותשובות גולמיות
שלוש רמות: `RunLog.log` — הכול, לקובץ `<תיקייה>.txt`; `RunLog.issue` — משפט בעברית
לרשימה שמוצגת בסיום (כדי שהמשתמש ידע **מתי** כדאי לפתוח את היומן); ו‑`.deepgram.jsonl`
— התשובות הגולמיות של התמלול, כדי ש"חסרות כתוביות" ייבדק ולא ינוחש. כל נסיגה (מודל
חלופי, ML Kit, קטע שנכשל, MKV שלא נוצר) חייבת לעבור דרך `issue`.

#### 4.12 FFmpeg כתוספת אופציונלית
FFmpegKit הרשמי הוצא משירות (ינואר 2025). הפרויקט משתמש ב‑fork תואם‑16KB
(`com.moizhassan.ffmpeg:ffmpeg-kit-16kb:6.1.1`, package `com.arthenica.ffmpegkit`)
מאחורי `-PwithFfmpeg`, עם source set נפרד ו‑`MediaToolFactory` ב‑reflection. כך ה‑build
הרגיל לא תלוי ב‑AAR נייטיבי, וה‑APK המלא נבנה ב‑CI. תצוגה מקדימה דורשת libass
בבניית ה‑FFmpeg; אם אין — מדולגת בזמן ריצה.

#### 4.13 חתימה קבועה
ראו "שדרוג" למעלה. `signingConfigs.debug` ב‑`app/build.gradle.kts` מצביע על
`app/debug.keystore` המחויב לריפו (חריג ב‑`.gitignore`). מפתח debug אינו סוד;
תפקידו היחיד הוא להישאר זהה בין בניות.

#### 4.14 פרטיות כאילוץ הנדסי
אין ספרייה שיוצרת תעבורה משלה; `PrivacyHttp` הוא הלקוח היחיד. שום מזהה משתמש או
מכשיר לא נכנס לבקשה. מפתחות נקראים מ‑`SettingsRepository` ונכנסים רק לכותרת
ה‑HTTP של הספק המתאים. יומן ו‑jsonl נשארים במכשיר. **אין להוסיף מפתחות לקוד או
לריפו, ואין להוסיף SDK של צד שלישי שמדווח הביתה.**

### 5. איך להוסיף / לשנות

- **מקור כתוביות חדש**: ערך ב‑`SourceStep`, פונקציה ב‑`SubtitlePipeline.acquire` שמדווחת
  `PipelineBus.step`/`stepUsed`, ומחזירה `Acq`. שמרו על הכלל: התזמון של המקור לא זז.
- **מנוע תמלול אחר**: מימוש `AsrEngine.transcribe(audio, language, model) → AsrResult(words…)`.
  `SpeechTranscriber` לא יודע מי הספק.
- **מנוע תרגום אחר**: מימוש `TranslationEngine`. שימו לב לסדר הפרמטרים (`machineTranscript`
  לפני ה‑lambda).
- **שינוי בכללי הפריסה** (תווים לשורה, cps, משך): קבועים ב‑`LineWrapper`, `CueSplitter`,
  `SubtitleTiming` — ויש להם בדיקות ב‑`core`.
- **שינוי בשרשרת FFmpeg**: רק ב‑`FfmpegMediaTool`; הממשק ב‑`MediaTool` מתעד מה כל
  פונקציה מבטיחה. כל שרשרת חדשה צריכה fallback, כי לא כל build של FFmpeg מכיל כל פילטר.
- **גרסה חדשה**: `versionCode`/`versionName` ב‑`app/build.gradle.kts`; push לענף
  `claude/hebrew-subtitle-video-app-8fbftq` מפעיל את ה‑CI.

### 6. בנייה
ה‑APK נבנה ב‑CI (`.github/workflows/build-apk.yml`) עם `-PwithFfmpeg`, JDK 17,
`compileSdk`/`targetSdk` 35. מקומית, ב‑Android Studio (Ladybug ומעלה):

```bash
./gradlew :app:assembleDebug -PwithFfmpeg      # APK מלא
./gradlew :app:assembleDebug                   # בלי FFmpeg (NoOpMediaTool)
cd core && gradle test                         # בדיקות הליבה
```

### 7. איך לקרוא יומן ריצה
שורות מפתח שכדאי לחפש ב‑`<תיקייה>.txt`:

| שורה | משמעות |
| --- | --- |
| `probe:` | כמה רצועות כתוביות, שפת אודיו, משך |
| `acquire: hashLookup=… movieHash=…` | האם היה חיפוש hash, ומה ה‑hash |
| `source:` | איזה מקור נבחר, כמה שורות, איזו שפה |
| `speech: dialogue audio via '…'` | איזו שרשרת חילוץ הצליחה |
| `speech: piece N […] words=… kept=… model=…` | תוצאת כל קטע תמלול |
| `speech coverage:` | סיכום: מילים, כתוביות, דקות על המסך, חורים, מעברים שניים |
| `Claude batch N attempt K: +X missing=Y stop=… in=… out=…` | כל אצוות תרגום; `stop=max_tokens` = תקציב הפלט נגמר |
| `Claude batch N narrowing(size=…)` | כמה שורות ניצלו בצמצום לקבוצות קטנות |
| `fallback:` | כמה שורות הושלמו ב‑ML Kit |
| `layout:` | כמה כתוביות פוצלו, כמה מהירות מדי |
| `verify:` | ffprobe על ה‑MKV אחרי הכתיבה: מסלולי כתוביות, עברית, attachments |
| `ISSUE:` | כל מה שהופיע ברשימת הבעיות בסיום |
